# 붕어빵 타이쿤 — 설계 문서

겨울 한 철 붕어빵 노점을 직접 굽고 경영해서, 플레이 방식에 따라 서로 다른 결말을 맞는 웹 게임.
이 문서는 "왜 이렇게 만들었는가"와 "어떤 규칙·수치로 돌아가는가"를 기록한다. 구현이 바뀌면 같이 고친다.

## 1. 왜 계속 하게 되는가

한 번 하고 끝나는 게임이 되지 않도록, **시간 단위마다 "다음에 할 것"이 하나씩** 있게 층을 쌓았다. 한 층이 질려도 위층이 붙잡는다.

| 층 | 플레이어가 느끼는 것 | 장치 | 주기 |
|---|---|---|---|
| 숙련 | "이번엔 더 잘 굽는다" | 굽기 타이밍 판정, 완벽 콤보 | 초 |
| 짧은 완결 | "한 판만 더" | 하루 영업 90초 → 정산 → 저녁 선택 | 2~3분 |
| 다른 결말 | "이번엔 다르게 해 볼까" | 겨울 20일 런, 엔딩 9종 | 40분 내외 |
| 수집 | "빈칸을 채우고 싶다" | 엔딩 도감, 신메뉴, 단골 대사 | 여러 런 |
| 영속 성장 | "한 게 사라지지 않는다" | 엔딩 계승 해금, 본점 | 며칠~몇 주 |
| 복귀 이유 | "쌓였겠다, 들어가 보자" | 본점 오프라인 수익(8시간 상한) | 하루 |
| 변주 | "판마다 다르다" | 동네, 날씨, 이벤트 카드 | 런·하루 |

설계 원칙 두 가지.

- **액션이 주인공이다.** 방치 수익과 영구 업그레이드는 다음 런을 조금 편하게 시작하게 할 뿐, 굽기 실력을 대체하지 못한다. 그래야 숙련의 재미가 끝까지 남는다.
- **엔딩은 점수가 아니라 플레이 방식이다.** 돈만 많이 번다고 모든 엔딩이 나오지 않는다. 완벽하게 굽기, 단골 챙기기, 메뉴 개발, 이벤트 선택이 각각 다른 엔딩으로 이어진다.

## 2. 하루 영업 (핵심 루프)

하루는 90초. 틀에서 굽고, 보온 진열장에 두면, 주문이 다 준비된 손님에게 **자동으로** 팔린다.
플레이어의 손은 "소 고르기"와 "틀 누르기" 두 가지만 한다(처음 버전은 손님도 눌러야 해서 정신없고 손이 꼬였다).

### 굽기
칸 하나당 탭 3번.

1. **반죽** — 빈 칸을 누르면 선택한 소로 반죽을 붓는다(재료 1개 소모).
2. **뒤집기** — 게이지가 차오른다. 초록 구간에서 누른다.
3. **꺼내기** — 반대쪽도 같은 방식. 꺼내면 보온대로 간다.

| 누른 시점(게이지) | 판정 |
|---|---|
| 0.6 미만 | 덜 익음 |
| 0.6 ~ 1.0 | 완벽 |
| 1.0 ~ 1.15 | 살짝 탐 (팔 수 있지만 값이 깎임) |
| 1.15 초과 (1.3에서 멈춤) | 탐 (폐기) |

두 면 중 나쁜 쪽이 최종 품질이다. 한 면이라도 타면 폐기, 한 면이라도 덜 익으면 덜 익은 붕어빵.
한 면 굽는 시간은 4초(버너 업그레이드로 3.4초, 2.9초). 빨라질수록 많이 굽지만 완벽 구간도 짧아진다.
틀은 4칸으로 시작한다(6칸은 처음 하는 사람에게 너무 정신없었다).

**손맛 장치**: 붕어빵 색이 반죽색 → 황금색 → 검정으로 변하고, 완벽 구간에 들어오면 틀이 초록으로 빛나며 "지금!"이 뜬다.
누르면 붕어빵이 튀거나 뒤집히고, 판정 글자가 틀 위로 떠오르며, 효과음과 진동이 난다. 소 버튼에는 "2개 더"처럼 더 구워야 할 개수가 뜬다.

### 보온대
기본 6개까지. 30초가 지나면 식는다. 꽉 차면 꺼낼 수 없어서 틀에서 타 버린다 — 미리 많이 구워 둘지, 주문 보고 구울지가 판단 거리다.

### 손님
주문(예: 팥 2, 슈크림 1)과 인내심 게이지를 갖고 최대 3명까지 줄 선다. 주문 전체가 진열장에 있으면 줄 선 순서대로 자동 판매. 인내심이 다하면 떠난다.

재료가 떨어지고 틀과 진열장도 비면 그날 영업은 바로 끝난다. 재료가 0인데 진열장에 남은 것이 있으면 "마감하기" 버튼으로 직접 끝낼 수 있다.

| 붕어빵 상태 | 받는 값 |
|---|---|
| 완벽 + 따뜻함 | 정가 × 1.2 |
| 완벽이지만 식음 | 정가 × 0.85 |
| 덜 익음 · 살짝 탐 | 정가 × 0.7 |

### 소(메뉴)
| 소 | 정가 | 얻는 법 |
|---|---|---|
| 팥 | 1,000 | 기본 |
| 슈크림 | 1,200 | 기본 |
| 고구마 | 1,300 | 신메뉴 개발 1 |
| 말차 | 1,400 | 신메뉴 개발 2 |
| 피자 | 1,500 | 신메뉴 개발 3 |
| 두바이 초콜릿 | 2,500 | 신메뉴 개발 4 |
| 민트초코 | 1,600 | 신메뉴 개발 5 또는 "퓨전 혁신가" 계승 |

재료는 소 구분 없이 1개 300원. 메뉴가 늘면 주문이 다양해져 더 어렵지만 단가가 오른다.

## 3. 저녁 (경영 선택)

영업이 끝나면 정산(매출 − 자릿세 2,000원)과 **이벤트 카드 1장**(두 선택지 중 하나)을 거쳐 **마을 지도**로 나온다.
마을에는 가게가 넷 있다.

| 장소 | 하는 일 |
|---|---|
| 재료상점 | 재료 10개 / 30개 구매(남으면 이월), 신메뉴 개발 |
| 가구상점 | 포장마차 장비 업그레이드 |
| 내 포장마차 | 다음 날 영업 시작 |
| 본점 | 저장하고 타이틀로 |

돈이 유일한 제한이다. 무엇을 먼저 사는지가 런의 방향이 된다.

| 업그레이드 | 효과(0→1→2단계) | 가격 |
|---|---|---|
| 붕어빵 틀 | 4 → 6 → 9칸 | 15,000 / 45,000 |
| 가스 버너 | 한 면 4 → 3.4 → 2.9초 | 10,000 / 30,000 |
| 보온 진열장 | 6개·30초 → 10개·45초 → 14개·60초 | 8,000 / 24,000 |
| 네온 간판 | 손님 ×1 → 1.2 → 1.4 | 12,000 / 36,000 |
| 자동 뒤집개 | 첫 면은 알아서 굽고 뒤집는다. 그동안 그 칸은 게이지가 흐려지고 눌러도 반응하지 않는다. 플레이어는 반죽 붓기와 꺼내기만 한다 | 30,000 |
| 새 가격표 | 값 +15%씩, 인내심 −10%씩 | 15,000 / 40,000 |
| 신메뉴 개발 | 다음 소 해금 | 10,000 / 20,000 / 30,000 / 45,000 / 60,000 |

| 이벤트 | 선택 A | 선택 B |
|---|---|---|
| 노점 단속 | 과태료 5,000원 | 자리 이동(내일 손님 −30%) |
| 방송 촬영 제안 | 출연(내일 손님 +50%) | 거절(단골 호감 +8) |
| 경쟁 포장마차 | 가격 인하(값 −20%, 손님 +30%) | 맛으로 승부(값 +10%, 손님 −10%) |
| 재료값 폭등 | 30개 묶음 7,000원 | 안 삼(오늘 발주 단가 ×1.5) |
| 단골의 부탁 | 재료 10개로 단체 주문(+15,000원, 호감 +8) | 거절 |
| 붕세권 지도 | 등록(내일 손님 +40%) | 아는 사람만(호감 +8) |
| 팥붕 vs 슈붕 | 팥붕 선언(내일 팥 유행) | 슈붕 선언(내일 슈크림 유행) |
| 릴스 떡상 | 올라탄다(최신 메뉴 유행, 손님 +20%) | 하던 대로(호감 +6) |
| 중고 트럭 매물 (6일차~) | 20,000원에 구매 | 지나침 |
| 전국 축제 초대 (트럭 보유) | 참가(트럭 엔딩 조건 충족) | 거절 |
| 프랜차이즈 제안 (11일차~, 매출 15만~) | 수락(프랜차이즈 엔딩 조건) | 거절(호감 +8) |

## 4. 시즌 런 (겨울 20일)

시작 자금 10,000원, 재료 40개(첫날 손님 수요가 30~40개라 하루는 버틴다). 정산 후 소지금이 마이너스면 즉시 폐업.

### 동네
| 동네 | 값 | 손님 수 | 인내심 | 단골 비율 | 최대 주문 | 해금 |
|---|---|---|---|---|---|---|
| 학교 앞 | ×0.85 | ×1.5 | ×1.0 | 20% | 2 | 기본 |
| 역 앞 | ×1.0 | ×1.2 | ×0.7 | 15% | 2 | 기본 |
| 시장 | ×1.0 | ×0.9 | ×1.2 | 40% | 3 | 기본 |
| 오피스가 | ×1.3 | ×0.6 | ×0.9 | 15% | 4 | "동네 맛집" 엔딩 |
| 전국일주 트럭 | 매일 위 넷 중 무작위 | | | | | "전국일주 트럭" 엔딩 |

### 날씨 (매일 무작위)
맑음(50%) · 눈(30%, 손님 ×1.3) · 한파(20%, 손님 ×1.1, 굽는 시간 ×1.25)

### 단골
다섯 명(고딩 민지, 박 과장, 시장 할머니, 택배 기사 준호, 고양이 집사 수아). 단골의 주문을 **전부 완벽한 붕어빵**으로 채우면 호감 +1.
호감은 런을 넘어 누적되고, 1 / 10 / 25에 도달하면 저녁에 그 단골의 이야기가 한 줄씩 열린다.

## 5. 엔딩 (9종)

런이 끝나면 위에서부터 조건을 검사해 처음 맞는 엔딩이 나온다.

| 순서 | 엔딩 | 조건 | 계승 해금 |
|---|---|---|---|
| 1 | 폐업 | 소지금 마이너스 | 위로금 500코인 |
| 2 | 황금 붕어 (히든) | 다른 엔딩 8종 수집 + 완벽률 85% + 매출 90만 | 황금 틀: 완벽 값 ×1.4 |
| 3 | 전국일주 트럭 | 트럭 구매 → 축제 참가 | 트럭 동네 |
| 4 | 건물주 | 매출 120만 | 시작 자금 +10,000원 |
| 5 | 프랜차이즈 대표 | 프랜차이즈 수락 + 매출 70만 | 본점 수익 ×1.5 (2호점) |
| 6 | 단골들의 사랑방 | 이번 런 단골 호감 150 | 단골 등장 확률 +10%p |
| 7 | 퓨전 혁신가 | 신메뉴 3개 개발 | 민트초코를 처음부터 보유 |
| 8 | 붕어빵 장인 | 100개 이상 굽고 완벽률 90% | 완벽 구간 확대(0.52부터) |
| 9 | 동네 맛집 | 그 외 | 오피스가 동네 |

### 밸런스 검증

`npm run balance`가 실력 3단계(초보·보통·고수) × 플레이 스타일 5가지로 20일 런을 자동 플레이해 엔딩 분포를 낸다.
수치를 바꾸면 다시 돌려서 아래 그림이 유지되는지 본다. (2026-11-15 측정, 조합당 200판)

| 플레이 | 초보 | 보통 | 고수 |
|---|---|---|---|
| 돈 위주 | 동네 맛집 | 프랜차이즈 83% · 건물주 14% | 건물주 96% |
| 품질 위주 | 동네 맛집 | 동네 맛집 | 장인 100% |
| 메뉴 개발 | 퓨전 | 퓨전 | 퓨전 77% · 사랑방 16% |
| 단골 위주(시장) | 동네 맛집 | 사랑방 67% | 사랑방 99% |
| 트럭 선택 | 트럭 | 트럭 | 트럭 |

- 매출 중앙값: 초보 37만~59만, 보통 80만~113만, 고수 87만~132만.
- 초보의 폐업은 1% 이하. 폐업은 재료를 안 사거나 무리하게 투자할 때만 난다.
- 자동 플레이는 사람이 아니다. 실제 사람의 실수 패턴(여러 칸을 동시에 놓침, 소를 잘못 고름)은 반영되지 않았다.

엔딩을 처음 보면 명성 3, 다시 보면 명성 1.

## 6. 본점 (영구 메타)

- 본점은 접속하지 않아도 **시간당 100 × 레벨 코인**을 번다. 최대 8시간분까지 쌓인다.
- **명성**으로 본점 레벨을 올린다(비용: 현재 레벨 × 2).
- **코인**으로 영구 업그레이드를 산다.

| 영구 업그레이드 | 단계별 비용(코인) |
|---|---|
| 시작 자금 +5,000원 | 500 / 1,000 / 2,000 |
| 시작 재료 +10개 | 300 / 600 / 1,200 |
| 손님 인내심 +5% | 800 / 1,600 / 3,200 |

## 7. 2030 타깃과 유행 요소

타깃은 20~30대. 붕어빵 자체가 이 세대의 겨울 밈(붕세권, 가슴속 3천원, 팥붕 vs 슈붕)이라 소재와 타깃이 맞는다.

밈은 몇 달이면 낡는다. 그래서 **유행 요소는 규칙이 아니라 데이터 표에 둔다.** 낡으면 코드를 건드리지 않고 `data.js`의 행만 갈아 끼운다.

| 요소 | 위치 | 내용 |
|---|---|---|
| 손님 말풍선 | `CHATTER` | "여기가 그 붕세권 맞죠?", "가슴속 3천원, 드디어 씁니다", "계좌이체 되나요?", "슈붕 안 먹는 사람이랑은 겸상 안 해요" 등 |
| 유행 이벤트 | `EVENTS` | 붕세권 지도, 팥붕 vs 슈붕, 릴스 떡상 |
| 유행 타는 소 | `FILLINGS` | 두바이 초콜릿(고가), 말차 |
| 유행 메커니즘 | `mods.trend` | 이벤트로 "내일의 유행 소"가 정해지면 그 소가 주문의 절반을 차지하고 값을 30% 더 받는다 |
| 결과 공유 | 엔딩 화면 | 엔딩 이름·매출·완벽률·도감 진행을 한 줄로 공유(모바일 공유 시트 또는 복사) |

고른 기준: **붕어빵 문화에 뿌리가 있어 오래가는 것**(붕세권, 팥붕/슈붕, 계좌이체)을 뼈대로 하고, 수명이 짧은 유행어는 말풍선 한 줄로만 쓴다. 실존 인물·그룹·브랜드 이름은 넣지 않는다.
`CHATTER`는 2026년 11월 기준이다. 시즌마다 갱신한다.

## 8. 그림과 화면

- **그림은 생성 이미지**다. 원본은 `assets/*.png`, 게임이 읽는 것은 `npm run assets`로 압축한 `assets/web/*.webp`(18MB → 2.5MB). 목록과 규격은 [ASSETS.md](ASSETS.md).
  붕어빵은 덜 익음·황금·탐 세 장을 겹쳐 놓고 익은 정도만큼 위 장을 드러낸다. 엔딩 삽화는 파일이 있는 것만 보인다.
  소 아이콘과 상점 물건 아이콘도 그림이다(자동 뒤집개 아이콘만 아직 이모지).
- **붕어빵 틀**: 실제 회전식 틀처럼 가운데 불을 둔 주물 원판 둘레에 칸(4·6·9개)이 놓인다. 굽기 게이지는 칸 테두리를 한 바퀴 도는 흰 점이고, 초록 호에 올 때 누르면 완벽이다.
- **글꼴**: 제목·버튼은 Jua(Google Fonts). 오프라인이면 시스템 글꼴로 대체된다.
- **분위기**: 눈 오는 겨울 밤의 포장마차. 화면 바탕은 나무판, 정보 카드와 버튼은 크림색 메뉴판, 강조는 천막의 빨강과 등불의 금색이다. 그림(구리 불판, 나무 매대)에서 색을 뽑았다. 처음의 남색 UI는 그림과 따로 놀아서 버렸다.
- **화면 흐름**: 타이틀(본점) → 동네 지도 → 영업 → 정산·이벤트 → 마을 지도(재료상점·가구상점) → 영업 … → 엔딩.
- 효과음은 음원 파일 없이 브라우저에서 합성한다. 타이틀에서 끌 수 있다.

## 9. 기술 구조

빌드 도구와 외부 의존성 없이 순수 HTML/CSS/JS(ES 모듈)로 만든다.

```
index.html, style.css
src/data.js     콘텐츠 표 (소, 동네, 날씨, 업그레이드, 이벤트, 엔딩, 단골)
src/sim.js      순수 게임 로직 — DOM을 모른다. 테스트 대상
src/save.js     localStorage 저장 (키 하나, 버전 필드)
src/main.js     화면 그리기와 입력
test/sim.test.js
manifest.json, sw.js, icon.svg   홈 화면 설치·오프라인 실행
```

- **콘텐츠 추가는 `data.js`에 행 추가**로 끝나게 했다. 엔딩·이벤트는 조건/효과 함수를 표 안에 둔다.
- **로직과 화면 분리**: 판정, 주문, 정산, 엔딩, 오프라인 수익은 `sim.js`의 순수 함수라 `npm test`로 검증한다.
- **저장 시점**: 저녁마다. 영업 도중 새로고침하면 그날을 다시 시작한다.

실행: ES 모듈이라 파일을 직접 열면 안 되고 로컬 서버가 필요하다.

```bash
python3 -m http.server 5173
```

테스트:

```bash
npm test
```

## 10. 아직 안 한 것

- **사람 플레이 검증.** 수치는 자동 플레이로 맞췄다. 실제 사람이 여러 판 해 본 결과로 한 번 더 조정해야 한다.
- 배경음악, 자동 뒤집개 아이콘(`up_auto.png`), 일반 손님 추가(지금 2명), 구매한 장비가 포장마차 그림에 반영되는 연출.
- 과금. 자동 뒤집개는 게임 안 돈으로 사는 장비다. 실제 결제를 붙이려면 서버와 결제 연동이 필요하다.
- 서버·계정·랭킹, 일일 챌린지, 결제, 스토어 출시.
- 런 중도 포기 버튼.
